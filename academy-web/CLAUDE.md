# academy-web (React 웹앱) 현황

## 목적
Streamlit 앱(운영 중, 절대 안 건드림)과 별개로, React 웹앱을 화면 단위로 새로 만들어서 점진적으로 전환 중.

## 전환 범위 (2026-08-22 확정)
스트림릿 메뉴 전체(9개)를 최종적으로 React로 다 옮기는 것이 목표. "완전 전환"이 맞으며, 지금 4개 화면은 그 중 일부(진입부 + 학생/학부모 외부 화면)만 완성된 상태. 나머지 8개 teacher 메뉴(내 수업 관리, 학생 명부, 출석 관리, 수강료 관리, 상담 일지, 성적 리포트, 문제 은행, 설정)도 이후 순서대로 화면 단위로 전환 예정.

## 완성된 화면 (더미 데이터로 구현됨, DB 연동 전)
- `/` : 학생 과제 인증 업로드 (과제인증 기능, 단계형 마법사)

## 작업 방식 (2026-08-22 개선 — 앞으로 이 방식으로 계속 진행)
기존 패턴(화면마다 Claude Design이 전체 페이지를 통째로 시안 제작 → Claude Code가 처음부터 구현)은 화면이 늘어날수록 사이드바/레이아웃을 매번 새로 반복 작업하게 되는 비효율이 있어 아래처럼 순서와 방식을 조정하기로 함.

1. **(선행 작업, 라우팅보다 먼저) 공용 레이아웃 틀 추출** — 기존 4개 화면(특히 대시보드)에 각자 박혀 있는 사이드바/상단바를 하나의 공용 Layout/Sidebar 컴포넌트로 뽑아냄. 이후 화면들은 이 틀 안에 "내용 부분"만 끼워 넣는 구조로 감.
2. **라우팅 네비게이션 연결**은 이 공용 틀이 있는 상태에서 진행 — 로그인→대시보드, 사이드바 메뉴 클릭→화면 이동. (8개 화면을 다 만든 뒤 마지막에 하는 게 아니라, 지금 시점에 먼저 함 — 나중에 반복 작업/재작업 줄이기 위함)
3. 이후 새 화면 작업 시:
   - Claude Design에는 전체 페이지가 아니라 "공용 틀 안에 들어갈 내용 부분"만 시안 제작 요청 (시안 크기·구현량 둘 다 줄어듦)
   - Claude Code에 넘길 때 "기존 Layout/Sidebar 컴포넌트 그대로 재사용, 새로 만들지 말 것"을 지시사항에 명시 — 매번 사이드바를 다시 분석/재구현하는 토큰 낭비 방지
   - `npm run dev`로 확인 → git add/commit/push (기존과 동일)
   - 백업 파일(복사본, node_modules 등)은 계속 git에서 제외 — Claude Code가 코드베이스 훑는 비용 절감에 도움됨(기존 습관 유지)

## 다음 단계 (진행 예정 순서 — 위 개선된 방식 반영)
1. ✅ **공용 레이아웃 틀(사이드바+상단바) 추출 — 완료 (2026-08-22, Claude가 직접 작업하여 로컬에 반영함)**

   - `Sidebar.tsx`는 그대로 `components/dashboard/`에 둠(삭제 도구가 없어 이동 대신 그 위치에서 재사용하는 방식으로 처리 — 기능상 동일)

   - `TeacherDashboard.tsx`/`.module.css`: 사이드바·레이아웃 껍데기 제거, 내용(KPI/반 목록/과제현황/리포트 테이블)만 남김 — 화면에 보이는 결과물은 이전과 동일
   - 검증: `tsc -b && vite build` 통과, Playwright로 `/`, `/login`, `/parent-report`, `/dashboard` 4개 경로 실제 렌더링 확인(사이드바는 `/dashboard`에서만 나타남, 콘솔 에러 없음 — 폰트 CDN 차단 경고만 있었고 이건 이번 작업과 무관)

   - 사용자가 `npm run dev`로 `/dashboard` 직접 확인 완료 — 기존과 똑같이 보임 (2026-08-22)
   - **아직 안 한 것**: git add/commit/push — 사용자가 직접 해야 함 (`cd academy-web` → `git add . && git commit -m "..." && git push`, 또는 저장소 루트에서 `git add academy-web`)
2. 라우팅 네비게이션 연결 (로그인 → 대시보드, 사이드바 메뉴 클릭 → 실제 화면 이동) ← 다음 작업

## 원칙
- 운영 중인 Streamlit 앱(app.py 등)은 절대 안 건드림
- 화면 단위로 하나씩 완성 후 다음 진행 (한번에 전체 X)
- Supabase DB는 Streamlit과 React가 공유해서 씀
- (신규) 반복되는 레이아웃 요소는 공용 컴포넌트로 먼저 뽑아두고, 새 화면은 그 위에 내용만 얹는 방식으로 진행 — 토큰/작업량 절감

## 참고 — 스트림릿 실제 메뉴 구조 (2026-08-22 기준)
