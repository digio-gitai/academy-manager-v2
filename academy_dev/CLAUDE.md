       훨씬 많게(또는 이상하게 붙어) 보이는 것처럼 나타났었음 — 근본 원인은
       1번(데이터 유실)이었고 2번(표시 버그)이 겹쳐서 더 헷갈리게 보인 것.
    "미완료 학생" 화면에 진행률 막대(초록=완료, 주황/빨강=남은 부분)도
    추가함 — 텍스트만으로는 한눈에 안 들어온다는 피드백 반영.
  - **아직 검증 안 됨:** 위 수정사항 전부 문법 검사만 통과했고 실제 dev
    DB로 브라우저에서 눌러보는 테스트는 아직 안 함. 다음에 이어서 할 때
    과제 항목을 나중에 추가/수정해도 기존 학생 진행 기록이 안 사라지는지,
    "1~2쪽" 같은 표시가 정상적으로 물결표와 함께 나오는지 이 2가지부터
    확인할 것.
- **출석부 연동은 설계만 해두고 지금 당장 코드로 연결하지 않음.** 과제인증은
  아직 별도로 테스트 중이라, 기존에 매일 실사용 중인 출석부(homework.py의
  class_homework/"전 수업 과제")는 건드리지 않기로 함. 나중에 이 abc 기능을
  운영 앱에 합칠 때는 이렇게 연결하면 된다:
  `hw_assign.py`의 `save_assignment()` 끝에서 `homework.save_class_homework(class_id,
  assigned_date, 항목요약텍스트)`를 한 번 호출해주면 끝 — homework.py나 app.py의
  출석 화면 코드는 전혀 안 건드려도 됨(이미 그 화면이 class_homework 테이블을
  읽어서 "전 수업 과제"로 보여주고 있기 때문). 항목요약텍스트는 hw_items를
  "문제집명 시작~끝쪽" 줄글로 이어붙이면 됨. 다만 이렇게 연결하면 과제인증에서
  저장할 때마다 그 반·날짜의 class_homework 내용이 자동으로 덮어써지므로,
  합친 뒤에는 출석 화면에서 수기로 과제를 직접 고쳐 쓰는 습관은 자제해야 함
  (고쳐도 과제인증에서 다시 저장하면 원래대로 덮어써짐).
- **다음 단계는 5단계(학부모 SMS 발송)** — 4단계 마무리 후 진행.

## 기술 스택

Python + Streamlit + Supabase(PostgreSQL) + Claude API(보고서) + GPT-4o(OCR 분석) + Google Vision OCR + 솔라피 SMS.
PDF는 Playwright/WeasyPrint, 수식은 LaTeX/SVG 렌더링 (HWP 변환 아님 — 편집 가능한 한글 수식 개체로 만드는 건
현재 기술로도 리스크가 커서 이 프로젝트에서는 채택 안 함).
