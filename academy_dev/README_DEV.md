# academy_dev — abc 메뉴 개발 전용 폴더

운영 중인 `streamlit-app` 폴더의 사본입니다. 여기서 무슨 짓을 해도 운영(매일 실사용 중인 앱)에는
영향이 없습니다. 단, **DB와 문자 발송만큼은 아래 절차를 꼭 지켜야** 안전합니다.

## 왜 DB 분리가 특히 중요한가

운영 앱은 로컬 SQLite가 아니라 **Supabase(클라우드 PostgreSQL) 하나를 공유**해서 씁니다
(`db_connect.py` 참고). 즉 dev에서 운영과 같은 `DATABASE_URL`을 쓰면, dev에서 테스트로 넣는
가짜 학생/성적 데이터가 전부 실제 운영 DB에 그대로 들어갑니다. 파일을 복사하는 것만으로는
DB가 분리되지 않는다는 뜻입니다.

같은 이유로 SMS(솔라피)도 운영 키를 그대로 쓰면 테스트 중에 실제 학부모 번호로 문자가
나갈 수 있습니다.

그래서 `academy_dev/.env`는 운영 값을 넣지 않고 **비워둔 상태**로 만들어놨습니다.
(OpenAI/Anthropic 키만 재사용 — 이건 데이터 위험이 없고 비용만 발생하는 키라 그대로 넣어뒀습니다.)

## 시작하기 전에 해야 할 일 (한 번만)

1. **Supabase에서 새 프로젝트를 하나 더 만드세요** (무료 플랜, 운영과 별개로).
   프로젝트 생성 후 Settings → Database → Connection string(URI, Transaction pooler 권장)을
   복사합니다.
2. `academy_dev/.env` 파일을 열어서 `DATABASE_URL=` 뒤에 방금 복사한 dev용 연결 문자열을
   붙여넣습니다. (운영 `.env`의 값을 절대 복사해오지 마세요)
3. 운영 DB의 테이블 구조(스키마)만 새 dev 프로젝트에 그대로 만들어야 앱이 정상 동작합니다.
   테이블이 많아서 스키마를 어떻게 옮길지는 다음 대화에서 같이 진행하면 됩니다
   (Supabase 대시보드에서 SQL 백업/복원 또는 pg_dump 방식).
4. SMS 발송까지 실제로 테스트해보고 싶을 때만 `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` /
   `SOLAPI_SENDER`를 채우세요. 이때도 받는 사람 번호는 본인 번호로만 테스트하세요.

## 실행 방법

`dev_실행하기.bat`을 더블클릭하면 `http://localhost:8502`로 뜹니다.
운영 앱(8501)과 동시에 켜놔도 서로 간섭하지 않습니다.

## abc 메뉴 개발 규칙

- 기존 메뉴 관련 코드(`app.py`의 기존 함수, `database.py` 기존 함수 등)는 **수정 금지**,
  새 파일/새 함수로만 추가하세요.
- 다 만들고 충분히 테스트한 뒤에만, 수업 없는 시간에 운영 폴더로 반영합니다
  (반영 절차도 다음에 같이 정리해드릴게요).

## 이 폴더에서 하면 안 되는 것

- `DATABASE_URL`에 운영 값 붙여넣기
- `SOLAPI_*`에 운영 값 붙여넣고 실제 학부모 번호로 테스트
- 운영 폴더(`..` 상위 경로)의 파일을 직접 열어서 수정
